# 20261108140000_mortgage_f9_property_value_basis — review notes (Mortgage F9)

**Owner decision 2026-11-08 (HOME VALUATION).** Store property market value and the
outstanding mortgage separately; equity = market value − associated secured debt;
prevent double counting (including a value entered as equity); handle existing records
conservatively without silently rewriting them; mortgage equity never applies to
unrelated loans.

**Statements.** `CREATE TYPE "PropertyValueBasis" AS ENUM ('MARKET_VALUE',
'EQUITY_ENTERED', 'UNKNOWN')`; one `ALTER TABLE "ManualAssetProfile"` adding
`assetKind TEXT` (nullable), `securedDebtAccountIds TEXT[] DEFAULT ARRAY[]::TEXT[]`,
`valueBasis "PropertyValueBasis" NOT NULL DEFAULT 'UNKNOWN'`. Generated by
`prisma migrate diff` from the schema change, byte-for-byte.

**Additivity.** No existing column, row, policy or grant is touched. No `UPDATE`, no
`DELETE`, no backfill. Constant defaults ⇒ catalog-only on PG11+ (no rewrite).

**Existing rows.** Read `valueBasis = UNKNOWN`, `securedDebtAccountIds = {}`,
`assetKind = NULL`. Nothing is inferred or restated: the app shows a disclosure and a
one-click "market value / equity" confirmation; only the USER changes a basis or a link.
Assets that have no ManualAssetProfile row at all are unaffected (the app upserts a
profile only on the user's own link/basis action).

**Why columns on the 1:1 profile, not a join table.** The secured-debt link is a fact
about the property, written only by the property's owner. On the profile it inherits the
exact RLS of the asset (visible-OR-owned account-subtree predicate, 20261015120000) with
no new table, policy or grant for review; a join table would need its own RLS, two FKs
registered with the account-reparenting audit, and an owner arm. The cost is no FK: every
read and write re-checks each id (owner or FULL same-Space link, `type = debt`, not
deleted, secured kind — mortgage / HELOC), so a stale id is ignored, never
subtracted. N is 1–2 per property.

**Old-client compatibility.** Full — the running application never selects these
columns; Prisma clients generated before this migration ignore them.
