# 20261108160000_mortgage_f1b_snapshot_installment_debt — review notes (Mortgage F1b)

**S2 ruling 2026-11-08** (required before Production AND before any Preview
regeneration). Mortgage F1 (#482) excludes installment loans from liquid net worth, but
`SpaceSnapshot` stored only total `debt` and `netLiquid`, so the stored-row check was a
range and the history boundary was a DATE constant (`LIQUID_NW_INSTALLMENT_EXCLUSION_FROM`).
This adds a stored column so the basis is read PER ROW.

**Statement.** One `ALTER TABLE "SpaceSnapshot" ADD COLUMN "installmentDebt" DOUBLE
PRECISION;` — nullable, the same numeric type as `debt` / `netLiquid`. Generated by
`prisma migrate diff` from the schema change, byte-for-byte.

**Additivity.** No default, no backfill, no `UPDATE` / `DELETE` / `INSERT`. Catalog-only
(nullable, no default ⇒ no table rewrite). No existing column, row, policy or grant is
touched; table-level grants and RLS policies on `SpaceSnapshot` cover the new column.

**Existing rows.** Read `NULL` = legacy row. Basis per row
(`lib/debt/liquid-net-worth.ts` → `liquidNetWorthRowBasis`): NOT NULL ⇒ new basis
(installments excluded; EXACT identity `netLiquid = cash + savings − debt + installmentDebt`);
NULL ⇒ the legacy RANGE identity and the OLD basis (installments subtracted), unless the
row's own identity proves it excluded debt (an F1-era row written before this column).
Nothing is inferred into the column; only snapshot writers fill it on rows they write.

**Old-client compatibility.** Full for this migration: code that predates it never reads
the column. **The F1b code DOES read it** (`getRecentSnapshots` selects every column, and
the writers set it), so this migration must be applied BEFORE the F1b code is deployed.

## Rollback (Preview only, S2 approval)

Run ONLY on Preview, ONLY with S2's approval, and ONLY after the F1b code is reverted (the
app reads and writes this column). One transaction; loses only the recorded installment
amounts (rows fall back to the legacy range check / old basis):

```sh
psql -1 "$PREVIEW_DATABASE_URL" <<'SQL'
ALTER TABLE "SpaceSnapshot" DROP COLUMN "installmentDebt";
DELETE FROM _prisma_migrations WHERE migration_name='20261108160000_mortgage_f1b_snapshot_installment_debt';
SQL
```

**Freeze pin.** `migration.sql`'s sha256 is pinned by
`lib/debt/snapshot-installment-debt-migration.test.ts`. Any change needs a new migration.

**Apply.** NOT before S2 line-reviews this SQL. Then coordinator only, `db:migrate:safe`,
Preview first. Mortgage hard gate: Preview only — never Production in this batch.
