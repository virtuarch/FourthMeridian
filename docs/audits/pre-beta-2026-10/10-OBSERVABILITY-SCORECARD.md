# 10 — Internal Observability Scorecard

Pre-beta audit of Fourth Meridian · `v2.6` · HEAD `cde8fa0e25d2c744933109b41611d1dd65a1f9a8` · 2026-10-21 · read-only, from code. What the operator can monitor from inside the product's own UI. Finding IDs `OBS-nnn`. Live state (whether `evaluate-alerts` has ever run on Preview or Production, Sentry delivery, `RESEND_API_KEY` presence per environment, row counts) is **UNVERIFIED**.

## 1. Verdict

Observability is wide but self-referential. The platform collects a great deal (a `JobRun` ledger, `RefreshExecution` with four child tables, `SyncIssue` episodes, `AiInvocation` per call, `PlaidWebhookEvent`, ~130 audit actions, per-account freshness clocks) and displays most of it across the Platform Operations cockpit, Pipeline, Providers, AI, Economics, Security posture and Customer Success. But the alerting path runs inside the 15-minute cron it is meant to watch, a dead cron leaves the "Alerts: Quiet" chip green forever because the posture has no age check, the `dead` job state is never alerted, an email "captured" in memory (no Resend key) counts as delivered and suppresses re-notification for 20 hours, no rule reads sync incidents or refresh executions, and every AI spend/allowance/failure signal rests on a fire-and-forget ledger whose write failures are only `console.warn`. Authorisation failures and API error rates are not collected at all. Weighted score: **5.2 / 10**.

Classification used below: **A** collected but not displayed · **B** displayed but not actionable · **C** actionable but not audited · **D** fully observable and operational · **N** not implemented.

**Signal-reliability notes (why a green indicator is not proof):**
- *"Alerts: Quiet, 0 of N firing"* is the newest succeeded `evaluate-alerts` run with no staleness test. If the dispatcher dies, this chip stays green indefinitely; the only contradiction is a `dead` row in the Attention table from job-health — which itself is computed from the same JobRun ledger and alerts nothing.
- *"Refresh pipeline Healthy, 0 of 1 failed"* counts executions that were recorded; executions whose ledger write failed are Sentry-only.
- *"Daily Brief Healthy, 1 generated"* is a count of DailyBrief rows, not of successful deliveries to users.
- *"Sources Stale 2 stale"* excludes REVOKED + owner-inactive items as "retired" (`health.ts:275-279`) and caps unhealthy rows at 20.
- *AI tiles / budget* are rate-card estimates over a fire-and-forget ledger; the kill switch and harness traffic pollute the failure fold.
- *"All emails delivered in the last N days"* (`OpsEmailDeliveryWidget.tsx:40`) means "handed to the provider"; auth/invite/security mails are not in that ledger at all (`email-health.ts:10-15`).
- *Health route* "ok" is computed on the same DB and behind a limiter that fails open when the DB is unreachable.
- *All platform widgets* are a snapshot at mount with relative ages frozen at mount.

## 5. Aggregate score

27 items, mean 4.9; weighted (D items ×1.5, N ×1, others ×1): **5.2 / 10**. Alerting reliability (items 10 and 26) and the AI ledger (items 14-19) weigh most for a beta that bills estimates against estimates. Confidence: high on code paths (all alert, jobs, AI, freshness authorities read and the top claims re-verified); low on live state (no JobRun, Sentry or Vercel access).

Verdict for the operator: GO for an owner-operated five-user beta conditional on OBS-002 and OBS-003 (one-line fixes) plus an external `/api/health` monitor; NOT GO for unattended operation until OBS-001 (dead-man's switch / age-gated posture) and OBS-004 (incident rule) land.
