# v2.6-SEED-1 — seed convergence

The seed modelled a product that no longer exists. This measures the gap, moves
the demo world onto Spaces a user can actually create, and proves coverage did
not shrink.

⚠️ **All work was done against a throwaway database (`fintracker_seedwork`),
created and dropped inside this slice. The working database was never seeded.**
Why that mattered turned out to be the headline finding.

---

## 1. THE WIPE — the finding that outranked the naming work

`prisma/seed.ts` performs an **unscoped** wipe:

```ts
await prisma.spaceAccountLink.deleteMany();
await prisma.financialAccount.deleteMany();
await prisma.transaction.deleteMany();
await prisma.space.deleteMany();
await prisma.user.deleteMany();      // ← no filter
```

The working database holds a **real account** beside the demo world:

```
Chris Hogan <chr.hogan1997@gmail.com>   11 accounts · 4,112 transactions · 748 snapshots
```

`npx prisma db seed` would have deleted it. The existing guard
(`assertNonProductionSeed`) asks *where* we are — `NODE_ENV`, `VERCEL_ENV` — and
would have raised no objection, because the environment was correct. It cannot
ask *whose data is here*.

**Fixed.** `assertOnlyDemoUsersPresent()` refuses when any user is not one of the
four demo accounts, and names them:

```
[seed] REFUSING TO RUN — this database contains account(s) the seed does not own:
         chr.hogan1997@gmail.com

       prisma/seed.ts wipes EVERY table, unscoped, including User. Running it
       here would delete the account(s) above and everything they own.
```

Verified by running the seed against the working database: it refused, named the
account, and the data was confirmed intact afterwards. `SEED_ALLOW_DESTRUCTIVE=1`
still overrides — the same explicit opt-in `db-guard.ts` uses.

"Refuse and say who" is recoverable; "wipe and report success" is not.

---

## 2. The gap: the seed modelled a product nobody can build

Creatable today (`lib/space-templates/registry.ts`): **`family` and `custom`.**
Everything else is `comingSoon` (disabled) or `hidden` (retired).

The seed produced, before:

```
PERSONAL 2 · HOUSEHOLD 1 · DEBT_PAYOFF 1 · TRIP 1 · INVESTMENT 1 · BUSINESS 1 · PROPERTY 1
FAMILY 0 · CUSTOM 0
```

**Six of eight Spaces were retired categories, and neither creatable type
appeared at all.** Every measurement taken over that corpus — including several
in this arc's own reports — described a product shape a user cannot build.

---

## 3. The instrument: states, not passing audits

`scripts/audit-seed-coverage.ts` (INFORMATIONAL, registered).

The REQUIRED gate passes on a fresh seed, and that is almost meaningless on its
own: an invariant over a corpus that cannot express its failure mode passes
**vacuously**. So the acceptance contract for a reseed is not "the audits still
pass" — it is **"every architectural STATE still exists"**.

46 states measured across Space shape, roles, visibility, account types, flow
types, ownership, chronology, lifecycle, event identity, transfers, debt,
snapshots, goals and holdings.

---

## 4. Before / after

```
=== COVERAGE DIFF (before → after) ===
  IDENTICAL — every state preserved
```

All 46 states unchanged. Resulting corpus:

```
CUSTOM 5 · OTHER 4 (platform Spaces) · PERSONAL 2 · FAMILY 1
```

**Coverage preserved, names not.** The mapping:

| Was | Now | Why the coverage survives |
| --- | --- | --- |
| Jane's / John's Space `PERSONAL` | unchanged | not user-pickable, but every real account gets one — the live path |
| Smith-Doe Household `HOUSEHOLD` | **Smith-Doe Family** `FAMILY` | the one live SHARED template; keeps the 2-member shape and BALANCE_ONLY links |
| Debt Payoff Tracker `DEBT_PAYOFF` | Debt Paydown `CUSTOM` | debt accounts + DEBT_REDUCTION goals are account/goal facts, not category facts |
| Japan Trip 2027 `TRIP` | `CUSTOM` | the no-accounts Space (day-zero rendering) |
| Investment Club `INVESTMENT` | `CUSTOM` | 3 members incl. VIEWER; holdings |
| JD Freelance LLC `BUSINESS` | JD Freelance `CUSTOM` | the ADMIN role |
| Austin Home `PROPERTY` | `CUSTOM` | real-asset account types |

This works because **the category was never load-bearing for any invariant.** It
selected a section preset and a hero definition; the architectural states come
from members and accounts. So the shapes move across untouched and the retired
presets stop being exercised — which is the point.

Gate on the reseeded scratch DB: **18/18 REQUIRED audits pass.**

## 5. What the seed still cannot represent

Five states were **absent before and remain absent** — pre-existing gaps, not
regressions, and each one makes a REQUIRED invariant pass vacuously in CI:

| Absent state | The invariant it disarms |
| --- | --- |
| `economicDate ≠ posting date` (0 rows) | the entire L8-B economic-chronology cutover |
| tombstoned / soft-deleted rows (0) | **`audit-event-identity` cannot catch a stale projection** — exactly the v2.6-EVENT-1 defect |
| events with 2+ observations (0) | pending→posted as ONE event: the whole point of L8 |
| rows with a resolved counterparty (0) | the transfer authority's persisted verdict |
| estimated snapshots (0) | FX-estimated disclosure |

This is empirical confirmation of a claim made earlier in the arc on reasoning
alone: **CI genuinely cannot catch the Plaid `removed[]` reprojection defect**,
because no seeded corpus has ever contained a tombstoned row.

Also unrepresentable today:

- **Multi-currency.** One currency across all seeded accounts, so FX conversion,
  `fxMiss` exclusion and the `unconverted` disclosure are never exercised.
- **`SUMMARY_ONLY` visibility.** Only `FULL` and `BALANCE_ONLY` are seeded.
- **`CONTRADICTORY` lifecycle rows** — the chronology audit's refusal path.

Closing these is the single highest-value follow-up, and a reseed is the cheapest
moment to do it. It was **not** done here: this slice's contract was "coverage
must not shrink", and adding states is a different change that deserves its own
measurement.

## Out of scope — recorded

1. **"Remove all remnants of decommissioned spaces" is only half done.** The seed
   no longer *creates* retired categories, but the retired categories themselves
   still exist across the codebase: `SpaceCategory` enum members, their
   `lib/space-presets.ts` section lists, `lib/space-hero.ts` definitions,
   `lib/perspectives.ts` perspective lists, and the `emergency_fund_progress`
   widget contract. That deletion is the v2.6-LEGACY-1 follow-up and needs the
   declared-baseline successor first (retiring `emergency_fund_progress` orphans
   `resolveExpenseBaseline`'s DECLARED rung).
2. **The five absent states** (§5) — the reseed that closes them.
3. **Platform Spaces use `category: OTHER`**, a retired category. They are system
   Spaces created by `ensurePlatformSpaces`, never user-created, so the picker's
   classification does not really apply — but they will look like retired-category
   Spaces to any census that does not special-case them.
4. **The seed's coverage instrument counts presence, not distribution.** A state
   with one row reads the same as one with a hundred. Sufficient for "did the
   reseed lose anything", insufficient for "is this corpus realistic".
5. **`SEED_ALLOW_DESTRUCTIVE=1` still bypasses the ownership guard**, by design.
   It is now the only way to wipe a database containing a real account, which is
   the intended shape — but it is a single environment variable between a
   developer and that outcome.

# v2.6-SEED-2 — which absent states belong where

The §5 gaps, classified against evidence rather than instinct.

## 7. The measurement: the live account is ground truth for realism

The working database holds a real account with real Plaid data beside the demo
world. Running the same coverage instrument against it — read-only — answers
"what does a real user's database actually contain?", and the attribution is
clean because **the seed contributed zero of every state below**:

| State | live DB | on the live Space | source |
| --- | ---: | ---: | --- |
| `economicDate ≠ posting date` | 2,822 | 2,822 | ALL real Plaid |
| estimated snapshots | 736 | 736 | ALL real Plaid |
| resolved counterparty | 351 | 351 | ALL real Plaid |
| tombstoned rows | 59 | 59 | ALL real Plaid |
| events with 2+ observations | 50 | 50 | ALL real Plaid |
| distinct currencies | — | **USD only (35 accounts)** | never occurs |
| `SUMMARY_ONLY` visibility | 0 | 0 | never occurs |
| `CONTRADICTORY` settlement | 0 | 0 | never occurs (null / POSTED / PENDING) |

Proportions on the live Space:

```
economicDate ≠ posting : 2,822 / 4,053  = 70%   ← THE NORM
estimated snapshots    :   736 /   748  = 98%   ← THE NORM
2+ observation events  :    50 / 4,381  = 1.1%
```

That reframes the question. Four of these are not pathological edge cases at all
— they are **what ordinary Plaid usage produces**, and two of them are the
overwhelming majority of real rows.

## 8. Classification

### → THE SEED (their absence made it *unrealistic*, not merely thin)

| State | Why the seed | Note |
| --- | --- | --- |
| **`economicDate ≠ posting`** | 70% of real rows. A seed at 0% models a world where cards authorise and post the same day, always. | **Done — see §9** |
| **estimated snapshots** | 98% of real snapshots. | Recommended next |
| **events with 2+ observations** | The seed already creates 4 pending rows and never posts them — an *incomplete lifecycle*, unrealistic on its own terms. | Recommended next |
| **resolved counterparty** | The seed already has 39 TRANSFER rows and zero resolved counterparties. Transfers between one's own accounts are ordinary. | Recommended next |

The pattern matters: in every case **the seed already contains the precursor and
stops short of the realistic outcome**. Completing those shapes is realism, not
added complexity — which is the bar this slice was asked to hold.

### → A TARGETED FIXTURE (pathological by construction)

| State | Why not the seed |
| --- | --- |
| **a STALE event projection** (tombstoned row whose event was never re-projected) | This one cannot go in the seed *even in principle*: it is an invariant **violation**, so `audit-event-identity` would fail on every fresh seed. The state that arms an invariant is sometimes the state that breaks it. Already covered by `lib/plaid/removed-tombstone-reprojection.test.ts`, which manufactures it deliberately (v2.6-EVENT-1). |
| **`CONTRADICTORY` settlement state** | Zero in real data. It is a refusal path — a provider contradicting itself. Pathological by definition. |

⚠️ Note the distinction this forced: **a tombstoned row is realistic; a stale
projection is not.** A healthy seed would tombstone *and* re-project, producing a
correct `WITHDRAWN` event. So "tombstoned rows" is a legitimate seed candidate,
while the defect state it was originally proposed to arm belongs in a fixture.
The §5 table conflated the two.

### → INTENTIONALLY UNREPRESENTED

| State | Why leaving it out is correct |
| --- | --- |
| **multi-currency** | Zero in real data — 35 accounts, all USD. Adding a EUR account would make the demo world *less* representative of a typical user in order to arm invariants that already have unit coverage (`lib/money/`, `V25-FINAL-1`). That is precisely the trade this slice was told not to make. |
| **`SUMMARY_ONLY` visibility** | Zero in real data. The redaction path is already exercised by `BALANCE_ONLY` (8 links); a third tier adds a permutation, not a new architectural state, and the resolver has parity tests. |

## 9. The one change made

Card purchases now carry an authorisation date, exactly as Plaid returns one.

Every seeded row passed `authorizedAt: null`, so `economicDateFor` returned the
posting date and the corpus could not express a chronology divergence at all —
leaving `audit-chronology-basis` and `audit-chronology-cutover` passing
vacuously.

The lag is **deterministic** (derived from the row index, never random, so two
seeds are identical) and applies **only to card-like spending** — Dining,
Shopping, Groceries, Travel, plus every pending row, which by definition has an
authorisation and no posting. Transfers, income and fees still post without one,
because that is what happens in reality. The economic date is still produced by
the write authority; the seed states evidence and never computes the date itself.

**Result:**

```
coverage diff:  economicDate ≠ posting date   ✗ ABSENT 0  →  ✓ 105
                (nothing else changed)
18/18 REQUIRED audits pass
two consecutive seeds produce identical coverage — deterministic
```

105 of ~350 rows is 30% divergence against the live account's 70%. Lower, and
deliberately so: only genuinely card-like categories carry an authorisation.
Directionally right rather than tuned to match one user.

- 485/485 unit tests · typecheck clean · 0 lint errors
- Scratch database created, seeded twice, verified, dropped
- The working database was never seeded; the live account confirmed intact

## Out of scope — recorded (SEED-2)

1. **Three seed-bound states remain** (estimated snapshots, 2+ observation
   events, resolved counterparty). Each completes a shape the seed already
   starts. Not done here: one state at a time, each with its own before/after,
   is how this stayed contained.
2. **The 70% vs 30% gap is unmeasured as a realism target.** There is no stated
   standard for how closely a seed should match observed proportions, and
   inventing one to justify a number would be worse than the gap.
3. **`authorizedAt` now exists on seeded rows for the first time.** Any future
   probe that assumed it null on seeded data would silently change meaning —
   none found, but the assumption was previously safe and no longer is.
