## 2. Root causes and fixes

**P0 — false debt-reduction claims.**
- *Cause:* Plaid PFC `LOAN_PAYMENTS` on depository→depository ACH pulls was stored as DEBT_PAYMENT, and several consumers (Brief prompt, AI filters, `transferTotal`, row text) read the stored flow.
- *Fix (#58 + #62):* one precedence contract, `resolveTransactionNature` in `lib/transactions/resolved-nature.ts`: user override > transfer-authority verdict > transfer evidence > provider category. Only `LIABILITY_PAYMENT` reduces debt, and every consumer is routed through it. Doc: `RESOLVED-TRANSACTION-NATURE-CONTRACT-2026-10-27.md`.

**P1 — historical rows.**
- *Fix (#61):* the repair script is hardened, with dry run by default, an `--apply` gate, a guarded all-or-nothing transaction, restore file + `--rollback`, and a Production guard requiring `--env=production --i-have-owner-approval=<ticket> --expect=<n>`.
- *Review found and fixed:*
  - guard columns were missing;
  - it partially committed;
  - rollback was impossible;
  - errors leaked the DB host.

**P2 — cash in transit.**
- *Finding:* the transfer authority cannot prove "left source, not at destination".
- *Fix (#63):* neutral ledger lines only, with **no definitive "In transit $X"** and **no total altered**:
  - "destination not yet confirmed";
  - "still pending at the destination";
  - "may be counted in both accounts until the sending bank posts it".

**P3 — HSA.**
- *Classification:* B, a presentation inconsistency. The restricted tier used the reported balance.
- *Fix (#63):* it now uses `countedBalance`, while HSA stays restricted and is never accessible.
- *Also fixed:* the as-of lens was carrying today's "reachable" figure into past dates.

**P5 — cutover.**
- *Finding:* the date-only constant was wrong for Preview (the basis went live 2026-10-27 ≈02:00Z), and a single date cannot describe the changeover day.
- *Fix (#64):* `NEXT_PUBLIC_ADJUSTED_CASH_BASIS_CUTOVER`, per environment (Preview default 2026-10-27). The note states UTC and the changeover day.

## 12. Calculation-basis cutover procedure

`V2.7-ADJUSTED-CASH-CUTOVER-RUNBOOK-2026-10-27.md`:
1. Plan a slot outside 23:30–00:30 UTC.
2. The owner sets `NEXT_PUBLIC_ADJUSTED_CASH_BASIS_CUTOVER=<planned UTC date>` in Vercel **Production scope** *before* the promotion build.
3. Promote and record the go-live instant (UTC).
4. If the UTC date differs, correct it and redeploy without cache.
5. Read-only verification of day C−1 / C+1 rows, using transaction-scoped `psql -1 … SET TRANSACTION READ ONLY` only.

Snapshots stay immutable, with no backfill. The changeover-window chart step is disclosed by the note.
